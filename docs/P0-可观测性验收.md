# P0 可观测性验收

日期：2026-09-17。范围为当前正式调用链 `main → api → service → workflow → database` 与 `knowledge.search`，不涉及旧实验 Agent、SSE 或 Qdrant。

## 交付

- `backend/observability.py`：按应用隔离的 OTel provider/Prometheus registry、ASGI 服务 Span、上下文传播、操作包装与白名单日志。
- `backend/api.py`：环境开关、provider 关闭、`/metrics` 与安全的请求错误记录。
- `service.py`、`workflow.py`、`database.py`、`knowledge.py`：服务/节点/检索/数据库方法 Span 与业务结果指标。没有新增数据库迁移，也没有更改业务事务或 checkpoint 字段。
- `observability/`：Collector 和 Prometheus 配置、Grafana 数据源与 Dashboard 预置文件；Dashboard JSON 可直接导入。
- `backend/tests/test_observability.py`：7 个测试，使用内存 Span exporter 和本地 registry。
- `backend/observability_smoke.py`：只允许规则演示环境的实际监控栈验收器。

## 测试证明的行为

1. 外部 `traceparent` 的 Trace ID 与父 Span 传播至 HTTP → agent.send → understand/resolve → knowledge.search → db.knowledge.active_chunks。同步线程与 LangGraph 调用保持父子关系；HTTP 响应提供 `X-Trace-ID`。
2. 多个请求同时运行时没有 conversation/turn 上下文串线；无效 traceparent 创建新 Trace。ID 只进入日志/Span，不进入指标标签。
3. 正常 approval interrupt 为 waiting、不是错误 Span。明确确认后执行；重复发送和重复决定记录 replay，退款仍只有一条。
4. 异常文本里放入合成敏感标记，密码、Cookie、Authorization、消息/Prompt、查询参数与 SQL 参数不进入导出的 Span、日志或指标；异常只记录受控类型，不记录 message 或 stack。
5. 注入失败后复用同 request_id 可以恢复原 turn；日志 sink 抛异常也不改变业务结果。
6. 默认关闭时没有 metrics 入口、导出或 Trace 响应头。多个应用有各自 registry，不发生重复指标注册或计数串用。

- 错误 Trace：`1685e1fd52408e5566dcdc048cdf0e69`；HTTP 500，`agent.understand`、`agent.send` 与请求 Span 的 `error.type` 均为 `InjectedFailure`。

Trace ID 仅供当前 Jaeger 实例查阅；内存存储重启会丢失，不能当作永久外部证据。冒烟脚本可生成新的证据。运行记录放在忽略的 `backend/runtime/observability-smoke.json` 与 `observability-fault.json`。
